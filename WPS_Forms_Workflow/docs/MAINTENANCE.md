# 维护规范

界面、Bridge与原三表共享文档处理内核，组件版本分别由实际代码和BUILD_INFO声明。程序没有模型API客户端；人或外层Agent使用相同表单/CLI。当前适用规则维护在README/PIPELINE和接口说明，发行变化记入CHANGELOG，执行日志与用户文稿不进入源码或Clean包。

## 数据和状态

- 首稿在规则扫描和必要检查后立即交付。无法判级的文字按正文保留原文原号并列待审项；内容缺口与格式保留分别报告。
- 每次分类或一批反馈由冻结原件与累积决定生成新稿，旧稿保留。来源树与目标组织树独立，来源和文件名都是数据。
- 分类表是完整计划；连续分类须继承已确认归类、顺序、题名及排除。单元展示题名不得改写派生源字节或使已确认排版失效。相同派生内容的ZIP成员元数据/顺序稳定。
- 核对任务、冻结来源、代码、模板和输出SHA，不能用颜色/隐藏表单代替绑定。表单不执行公式、宏或外链。
- 待生成、保留、未定位和执行失败分开。通过本稿检查后关闭已应用项，不重复送审；未知关系不靠改写原文迎合规则。

## 识别与保真

标题/列表编号实例隔离，图表使用SEQ/REF；量值保护先于编号识别。源图题结合真实邻接、版式差异及语义判断，一图一题约束可用于消歧，普通解释句保持正文。完整迁出获准旧号，技术数值与子图标记保留。检查器从原件独立复算引用与编号，不只重放装配声明。

前置信息根据实际范围和正文对应关系识别，不按第一页或单个元信息词全局删除。目录先提取章节线索再与正文核对，封面/目录/页眉/节范围保护。真实文章题名保留；边界不明局部保留。

原公式、不透明OLE/VML及其关联资源保持。未知完整REF保留缓存内容并明确降级；缺图必须列实际媒体缺口，不能用占位宣称原图已搬入。不完整书签只处理不完整元数据，有效书签与正文保持。数学内容、数字和原始二进制不猜改。

## 开发与验收

最小复现→失败用例→局部修复→相关专项→发行核对。优先复用已有测试；不因文档维护重复全量，不把旧版通过当本版实跑。来源/数字授权、模板保护、对象保真与独立检查不能为消除失败而放宽。源码、公开模板、说明、组件清单与发布包按同一快照核对。

程序结果、真实办公软件操作及页面视觉分别记录。用例范围不能换算成未知报告准确率。输入均用自造公开样本；运行数据/评审答案/草稿/个人配置留在源码之外。

## 显式清理

清理仅处理用户明确结束的批次，默认预览。先保存核对各阶段总稿，再删除固定产物；原件、任务外模板、手改稿和未知文件保护。--keep-latest保留最新任务与完整依赖链。PENDING可续清、CLEANED关闭旧表；清理不是跨代码迁移。任务提交与清理使用同一OS锁，不能在手工编辑内部产物时执行。诊断READY仅表示安装身份一致，不等于文档或页面验收。
