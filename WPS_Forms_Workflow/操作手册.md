# WPS 三表工作流操作手册：每轮输入、输出与下一轮目录

适用：独立三表 **v0.1.6**，内核协议0.5.7。更新日期：2026-10-23。

本批增加统一诊断身份和按需清理，已有图题、中文层级、对象/引用和三表流程沿用。DOC转换、物理首页、封面/目录等历史验证保持原范围，不因版本变化重标为本轮通过。详细适用范围见README，实际执行记录见本批REPORT。

## 清理阶段稿之外的中间数据

双击包内`一键清理中间产物.cmd`清理包内outputs；也可把实际任务父目录拖上去。它先保存、核对每轮总稿，再清理已经交稿任务的扫描、冻结副本、单篇、定位、检查和表单等内部产物。仅留总稿后旧02/03失效；保留Word不等于保留可续办任务。原输入和用户模板必须仍有相同外部原件，否则跳过该任务。

```powershell
python cleanup_tool.py "D:/任务"                        # 只预览
python cleanup_tool.py "D:/任务" --apply                # 执行，仅留阶段总稿
python cleanup_tool.py "D:/任务" --apply --keep-latest  # 最新任务及依赖链保持可续办
```

每轮清理后目录例如：

```text
D:/任务/
  首稿01/
    阶段总稿/draft_001_build_001_master_内容哈希.docx
    CLEANED_TASK.json
    .maintenance.lock
  分类02/
    阶段总稿/...
    CLEANED_TASK.json
  cleanup_history.jsonl
```

未登记根文件保留。未完成任务、原件改变、手改单篇、未登记Office文件、目录链接或正在由CLI提交的任务不会强删，会列原因。手改总稿按实际文件保留；已有不同保留文件不覆盖。中断时总稿已先保存，按同一命令继续读取CLEANUP_PENDING记录；部分完成有明确状态，不能写全部已清。

## 1. 先记住这四条

1. **01只负责建立一批新任务。** 首次扫描后就有总稿，后续通常不再运行01。
2. **下一轮输入是“上一轮任务目录＋其中最新的02或03表”。** 上一轮总稿用于查看，不作为重新整理的源文件。
3. **每次分类或反馈都指定一个全新的输出目录。** 不覆盖上一轮目录；R01、R02等外层名称由你决定。
4. **每轮先取得新稿，再继续核查。** 未定文字保留原文原号、按正文呈现；局部悬置不要求清零后才交稿。整篇未接入或内容缺口需单列。

## 2. 推荐的目录摆放

把程序、资料、每轮结果分开。以下为示例，`工作批次/十月月报`需要按你的实际任务建立：

```text
WPS文档整理/
├─ WPS_Forms_Workflow/       ← 本机程序目录；移植时也可用解压后的同名目录
│  ├─ forms_tool.py
│  ├─ forms/01_输入.xlsx
│  └─ templates/
└─ 工作批次/十月月报/
   ├─ 原始资料/                         ← 原始DOC/DOCX留档
   ├─ 来源_DOCX/                        ← 01中填写的接入根目录
   │  ├─ 任务甲/报告A.docx
   │  └─ 任务乙/报告B.docx
   ├─ 输入/01_输入.xlsx                 ← 首次接入表
   └─ 运行/
      ├─ R01_首稿/                      ← scan生成
      ├─ R02_分类/                      ← classify生成
      ├─ R03_反馈1/                     ← feedback生成
      ├─ R04_反馈2/                     ← 下一批feedback生成
      └─ R05_分类调整/                  ← 需要时再次classify生成
```

`来源_DOCX`中的相对子目录会作为程序建议归类的依据。任务树模式保留子文件夹；普通月报也使用同一入口。标准报告默认整体处理；月报只有可靠、完整的拆分建议才可在02确认拆分。

**不要提前手工建立R01、R02等输出叶目录。** 只建立`运行`父目录，由程序创建每轮新目录。程序要求`--out`或首次扫描的输出目录尚不存在。

## 3. 本机运行前的变量

以下命令在PowerShell中执行。先填一次这些变量，之后各轮直接复用：

```powershell
$ToolRoot = 'D:\DocFlow\WPS_Forms_Workflow'
$Py = 'D:\Python312\python.exe'
$Tool = Join-Path $ToolRoot 'forms_tool.py'

# 以下为示例批次位置，按实际任务修改。
$Batch = 'D:\Documents\MonthlyBatch'
$Sources = Join-Path $Batch '来源_DOCX'
$Input = Join-Path $Batch '输入\01_输入.xlsx'
$R01 = Join-Path $Batch '运行\R01_首稿'
$R02 = Join-Path $Batch '运行\R02_分类'
$R03 = Join-Path $Batch '运行\R03_反馈1'
$R04 = Join-Path $Batch '运行\R04_反馈2'
$R05 = Join-Path $Batch '运行\R05_分类调整'
```

把待处理的DOCX和DOC放进`$Sources`后再开始。换电脑时，把`$ToolRoot`改为程序解压位置，把`$Py`改为该电脑可用的Python。核心需要Python3.10+与`lxml==6.1.3`；DOC转换或WPS首页检查另需本机WPS与pywin32；纯DOCX可关闭首页离线运行，不依赖模型服务、python-docx、Pillow或openpyxl。

也可在程序目录使用`run.cmd forms ...`，它调用相同入口。不要混用不同版本程序接续同一任务：本版会核对运行代码指纹，表单旧任务的跨代码迁移没有在此次补丁中新增。

## 4. 第0步：生成01输入表

```powershell
& $Py -X utf8 -B $Tool init --out $Input --root $Sources --run $R01
```

**此时新增：** `输入/01_输入.xlsx`。还没有总稿，也没有R01任务目录。

打开01检查：

| 单元格 | 内容 | 本例 |
| --- | --- | --- |
| B9 | 接入根目录，唯一必填 | `$Sources`对应的完整路径 |
| B10 | 目标模板 | 留空使用程序自带模板 |
| B11 | 首稿输出目录 | `$R01`对应的完整路径 |
| B12 | 总稿名称 | 可填写如“十月工作汇总” |
| B13 | 核查方式 | 建议初次使用保留“人工核查” |
| B14 | 启用WPS首页检查 | 选择启用/关闭；默认关闭，兼容wps/off |
| B15 | DOC转DOCX预处理 | 选择启用/关闭；默认启用，遇DOC才启动WPS |

单元格填实际路径文字，不填`$Sources`变量名，也不在路径外加引号。上面的`init`命令已把变量的实际值写入表。

另一种方法是复制包内`forms/01_输入.xlsx`后手填B9/B11。**两种方法选一种**；已有同名输入表时，不再对同一路径运行init。

## 5. 第1轮：扫描后立即生成首稿

保存并关闭01，然后执行：

```powershell
& $Py -X utf8 -B $Tool scan $Input
& $Py -X utf8 -B $Tool status $R01
```

### 输入是什么

- `输入/01_输入.xlsx`中的根目录、模板及任务设置。
- 根目录下递归找到的DOCX和DOC；DOC先转换，失败明确列缺口。

### 会多出什么

程序创建`运行/R01_首稿/`，其中包括：

```text
R01_首稿/
├─ 01_输入.xlsx                         ← 本轮接入表的留档副本
├─ 02_扫描核查.xlsx                     ← 下一步调整分类/顺序/取舍用
├─ 03_反馈提交.xlsx                     ← 下一步提交局部反馈用
├─ DELIVERY.md                         ← 本轮交付与状态说明
├─ forms_state.json                    ← 本轮身份、父链及状态
├─ inventory.json                      ← 来源树、单元建议、忽略项
├─ approved_plan.json                  ← 本轮实际采用的组织计划
├─ page_facts.json                      ← 首页读取结果；off时也有说明
├─ preparation_check.json              ← 本轮单元准备检查
├─ draft_001.status.json                ← 首稿/分类装配的状态快照
├─ source_scan/                        ← 冻结的来源/模板、原始扫描与候选
├─ prepared/                           ← 准备后的模板及必要的派生单元
└─ draft_001/                          ← 本轮Word处理内核任务
   ├─ state.json
   ├─ DELIVERY.md
   └─ build_001/
      ├─ documents/
      │  ├─ master.docx                ← 这一轮的总稿
      │  ├─ S0001.docx                 ← 单来源成稿，数量由纳入来源决定
      │  └─ ...                        ← 还可能有数学处理的JSON辅助记录
      ├─ locators/                     ← 反馈定位索引
      ├─ checks/                       ← 内容/对象/编号等检查
      ├─ execution/                    ← 装配执行记录
      └─ assembled/                    ← 中间装配文件
```

日常查看**documents里的master.docx**。`assembled`是中间阶段，通常不作为交付稿。

首稿先按完整来源生成，不等待分类或模型评审；无法判级的纯文字保留原文原号并按正文呈现，实际图片/组图/数据表先有编号。未定项仍会出现在03等记录中。

### 下一轮用哪个目录

- 调整整篇/单元组织：打开 **R01的02**，下一轮输入目录就是`$R01`。
- 直接改局部问题：也可以打开 **R01的03**，直接由R01建立反馈新稿，不强制先提交02。
- **R01里的01只是接入留档，后续通常不再scan它。** 它的B11仍可能是最初的R01路径。

### 两种自动目录情况

- B11留空且不传`scan --run`时：程序在**程序目录**下的`outputs/首稿_时间_随机号/`建立任务。以命令返回的`run`字段为准，不要到来源目录猜结果位置。
- B13选“接受程序建议”时：先生成首稿目录，再自动创建旁边的`首稿目录名_分类稿`（重名时带数字后缀）。后续使用返回`run`所指向的分类稿目录中的表。本手册的R01→R02例子使用默认人工核查。

## 6. 第2轮：提交分类，生成新总稿

打开`R01_首稿/02_扫描核查.xlsx`，从第9行开始填写：

| 列 | 填写方式 |
| --- | --- |
| A:D | 程序事实，保持原值，不删除/排序/移动行 |
| E | 接受建议、整篇保留、按建议拆分、不纳入 |
| F | 目标归类，如`任务甲/试验分析`；空白为根层 |
| G | 顺序，1—999999的整数；用它改顺序 |
| H | 展示题名；空白使用来源建议题名 |
| I | 说明，不自动解释为程序指令 |

在B6选择 **“确认本表”**，保存并关闭表格：

```powershell
& $Py -X utf8 -B $Tool classify $R01 --out $R02
& $Py -X utf8 -B $Tool status $R02
```

**输入：** R01完整任务目录，以及刚保存的`R01/02_扫描核查.xlsx`。

**新增：** `R02_分类/`。它有新02、新03、新总稿和新一套任务记录；还多出`submitted_classification.xlsx`，保存本次实际提交的分类表。来源、扫描及准备数据会随新目录保留。

新总稿通常是：

```text
R02_分类/draft_001/build_001/documents/master.docx
```

确认拆分后，documents中的单来源成稿可能变为`S0001_U001.docx`等单元成稿；不应把它们与整篇重复纳入。新02回填本次生效的归类、顺序、展示题名和排除决定。

**下一轮打开R02的03提交反馈，或打开R02的02继续分类。不要再从R01的表沿用旧分支。**

## 7. 第3轮：提交一批局部反馈，生成新稿

打开`R02_分类/03_反馈提交.xlsx`。程序已有行的A/B/C/I保持不动；D:H是本条修改意图。新增意见使用程序预留空白行，可填B/C。

例如新增一条“某段字号改14磅”：

| 字段 | 填写示例 |
| --- | --- |
| B 文档ID/定位 | `master`，或当前定位索引中的`master \| S0001:b000003` |
| C 原文片段 | 能唯一匹配的原文，避免只填到处重复的短标题 |
| D 修改类型 | 字号 |
| E 填写值 | 14，不加“磅”字 |
| F 补充说明 | 说明问题；自然语言不会自动转成脚本动作 |
| G 作用范围 | 仅此处 |
| H 本条决定 | 提交修改 |

标题级别填**来源级别1—5**；正文/列表转换选相应类型；字号/缩进/段距用磅，行距用倍数。具体类型表见程序README。当前“本单元/全文”范围记录为需明确计划的保留项，不自动扩大执行。

未处理的行可以暂缓；“保留原样”用于明确接受程序已有事项的原状。检查后才关闭已应用项。不要删除程序已有问题行。每批可按完整类别/约50条安排，新意见有30条预留空白行，可继续下一批。

在B6选择 **“提交本表”**，保存并关闭表格：

```powershell
& $Py -X utf8 -B $Tool feedback $R02 --out $R03
& $Py -X utf8 -B $Tool status $R03
```

**输入：** R02任务目录及`R02/03_反馈提交.xlsx`。

**新增：** `R03_反馈1/`中的新总稿、新02、新03，以及：

| 本次新增文件 | 用途 |
| --- | --- |
| submitted_feedback.xlsx | 本次实际提交的03留档 |
| feedback_ledger.json | 本批各意见的应用、保留、未定位、失败等结果 |
| 反馈处理回执.xlsx | 人可以直接查看的只读结果，**不是下一次提交表** |

反馈轮不保证具有首稿/分类轮相同的所有顶层辅助文件，例如不应以缺少`draft_001.status.json`或`preparation_check.json`推断没有新稿；看当前status和实际产物。

**下一轮使用R03的新03。** 已应用项检查后关闭，暂缓/未定位等继续保留；单批没有解决所有问题，也仍可交付带保留项的新稿。

## 8. 第4轮及以后：沿最新目录连续推进

继续提交第二批反馈：

```powershell
# 先填写R03中的03，B6提交本表。
& $Py -X utf8 -B $Tool feedback $R03 --out $R04
& $Py -X utf8 -B $Tool status $R04
```

反馈之后想改归类/顺序/展示题名，也可再分类：

```powershell
# 先填写R04中的02，B6确认本表。
& $Py -X utf8 -B $Tool classify $R04 --out $R05
& $Py -X utf8 -B $Tool status $R05
```

当前版本会保留相同来源/单元的有效结构和局部排版决定。只改顺序或展示题名，不应撤销先前已确认的字号、结构、归类和取舍。

| 动作 | 读取哪轮及哪张表 | 输出到哪里 | 接下来填哪张表 |
| --- | --- | --- | --- |
| init | 来源路径/任务设置 | 输入/01_输入.xlsx | 01 |
| scan | 输入/01_输入.xlsx | R01_首稿 | R01/02或R01/03 |
| classify | R01＋R01/02 | R02_分类 | R02/02或R02/03 |
| feedback | R02＋R02/03 | R03_反馈1 | R03/03或R03/02 |
| feedback | R03＋R03/03 | R04_反馈2 | R04/03或R04/02 |
| classify | R04＋R04/02 | R05_分类调整 | R05/02或R05/03 |

如果把填写后的表另存了名字或放到别处，命令加`--form "填写后表的完整路径"`；仍要传它所属的任务目录。例如R03导出的表，只能对R03提交，不能因名称同为03就套到R02。

02是**完整计划**：只改G时保留其他回填值。清空F是移到根层、清空H是回到来源题名，均不表示沿用旧值。03处理回执只供查看；下一次始终填新的`03_反馈提交.xlsx`。

## 9. 到底打开哪一个Word？

通常是：

```text
你本次--out目录/draft_001/build_001/documents/master.docx
```

`draft_001`、`build_001`是**单个任务目录内的编号**；R03里仍叫draft_001，不代表它回到了全批次第一稿。整个批次的先后顺序由外层R01/R02/R03表示。

实际路径以本轮`draft_001/state.json`的`deliverables`中`id=master`的`file`字段为准，该file相对于`draft_001`。可用以下只读命令查看，无需手工理解或修改JSON：

```powershell
$Run = $R04                    # 改为你要查看的这一轮
$Core = Join-Path $Run 'draft_001'
$State = Get-Content -LiteralPath (Join-Path $Core 'state.json') -Raw -Encoding UTF8 | ConvertFrom-Json
$Master = $State.deliverables | Where-Object { $_.id -eq 'master' }
Join-Path $Core $Master.file
```

## 10. 每轮状态怎么看

每次生成后读一次本轮DELIVERY或执行一次status即可，status是读取现有记录，不重新装配：

```powershell
& $Py -X utf8 -B $Tool status $R04
```

| 状态/字段 | 意义与后续操作 |
| --- | --- |
| COMPLETED_LOCAL_CHECKS | 当前本地检查完成，可查看总稿；不等于所有未知报告语义都已证明正确 |
| COMPLETED_WITH_RETAINED_ITEMS | 已交付，仍有保留事项；查看新03，按需继续下一批 |
| NEEDS_REPAIR | 查看是否已有总稿及具体缺口/失败；已有稿也可能带整篇缺口，不把它说成完整搬入 |
| ERROR | 本次命令未正常完成，读error原因；新目录可能未创建，也可能是失败现场，保留上一轮可用稿 |
| latest.master.status | `PRODUCED`类状态表示总稿已经生成，可能带缺口后缀 |
| latest.receipt_integrity | PASS说明当前回执核对通过；仍需看保留项和内容缺口 |

退出码0可以表示“交出了明确标记缺口的草稿”，不是保证所有内容都已完整导入。不要只看进程退出码。

有错误时保留现场，用新的输出目录再次提交，不在已有输出目录原地重跑。输入非法、表单属于别批、冻结依据或手工改稿破坏绑定时，需要先解决具体原因，不能手改SHA/状态字段绕过。

## 11. 哪些资料必须保留

- 日常可将最新master.docx复制出来作为交付件；继续修订仍需要对应的**完整任务目录**。
- 保留这条主线的父目录。当前协议会引用父状态/决定，不把“只剩最后一份Word”当作可继续反馈的任务包。
- 每轮会保留来源/模板快照、扫描记录、准备数据和新稿，磁盘会增加；当前没有扫描缓存或仅存差异的机制。
- 同一批次通常使用冻结来源。后续修改/新增原始文件，不会自动进入已有R02/R03；需要从新的01建立新扫描任务，重新确认组织，不能静默套用旧表。
- 想手工改Word时另存一份。不要覆盖绑定的生成稿后再套旧03；程序不能自动吸收那份手工改稿作为新来源。
- 从R01分叉产生两条修订线时，程序不会自动合并两条线的决定；主线应沿自己选定的最新目录连续推进。

## 12. DOC与WPS首页检查

首页在识别前只读副本提取。真实题名保留，作者/机构/日期及目录有证据才排除，不按第一页整页删正文，不用截图或OCR。标题提取成功不代表所有前置范围都识别准确；未定部分仍保留并列事项。

## v0.1.5 首稿看到“原自动编号待核”怎么办
这表示本处标签程序未可靠解析，原文字和对象已保留，不是整篇缺口。完整自包含旧编号定义会原生迁移，不会无故替换。需调整角色时使用03“改为正文/改为列表/标题级别”及明确定位；本版不猜原标签。原始数据在source_scan/inputs或冻结来源，收尾事项给出来源/位置/原因。确定接受当前显示时，可在最新03已有事项选择“保留原样”；仍按新目录提交，检查后关闭。中文父章及数字子节按相对结构处理，来源名称和分组所占深度另叠加。

03同一来源块的同一结构问题只出现一行，通常定位到master；单篇/总稿镜像和结构内部不同kind保留在绑定记录，不需要重复填四遍。新增的格式意见依旧按B列指定文档/位置生效。倍数、次数等量值有歧义时先保正文，不要为了少一条待审把真实数值当章节号删去。

例如B列为`master | S0001:b000010`、类型为字号、值为12，只改总稿此处，单篇不变。另一轮对`S0001 | S0001:b000010`填14，只改单篇，总稿仍12。结构角色/级别属于来源判断，会重建所有使用该来源的输出及依赖编号；格式范围与结构判断的作用范围不同。
