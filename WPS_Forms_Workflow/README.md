# WPS 三表文档整理 · 0.1.6

基于 `20261022.caption-role-r2`，复用原 Word→Word 内核协议0.5.7。提供目录树与三份 Excel 表单，不含模型 API。人或外层 Agent 使用相同入口。当前独立三表与旧WPS、Bridge、HRS保持各自身份。

当前构建在原事实层补充`hyperlink_ranges`（原链接记录、文字和源定位保留），供Bridge保留原生链接。独立扫描校验核对范围、文字及目标，原编号事实审计继续执行；三表0.1.6、协议0.5.7及正文识别/编号/模板规则保持，具体构建号见BUILD_INFO。

## 诊断身份与一键清理（0.1.6）

`python report_tool.py doctor`、`python forms_tool.py doctor`和`run.cmd doctor`同时返回`forms_version`、`kernel_protocol`、`build_id`。三表版本描述此工具，0.5.7是复用内核的协议号。实际代码、BUILD_INFO、config和发行清单不一致时，诊断报错；`READY`只表示当前安装诊断，不等于文档识别/页面验收通过。

完成一批整理后，可将**任务父目录**拖到`一键清理中间产物.cmd`；双击而不传路径时处理本包`outputs`。它会执行清理：先保存并核对各阶段总稿，再清理已完成任务的扫描、冻结副本、单篇稿、IR、定位和表单等中间数据。用户输入原件和任务外模板保持；未完成任务、原件缺失/已改变、手工修改的单篇或产物目录内未登记Office文件会跳过并给出原因。未登记根文件保留。它只处理三表任务，不是全项目删除工具。

**仅留总稿模式会结束旧02/03接续能力。** 之后需要整理时，从输入原件新建任务；不可将清理后的Word当成完整任务记录。还要继续提交反馈时，使用`--keep-latest`，完整保留所选目录最新任务及其修订依赖链。依赖链可能包含多轮，程序不会为腾空间擅自切断它。

```powershell
# 默认预览，不删除、不创建清理日志
python cleanup_tool.py "D:/任务"
# 执行：只保留阶段总稿及最小清理记录
python cleanup_tool.py "D:/任务" --apply
# 执行：额外保留最新任务及依赖链
python cleanup_tool.py "D:/任务" --apply --keep-latest
# 等价入口
run.cmd cleanup "D:/任务" --apply
python forms_tool.py cleanup "D:/任务" --apply
```

总稿留在各轮目录的`阶段总稿/`，文件名带稿次/build及内容哈希；手改总稿保留实际字节并记差异，不覆盖已有不同文件。每轮仅留下`CLEANED_TASK.json`和极小的`.maintenance.lock`等必要控制记录，父目录累计在一个`cleanup_history.jsonl`中。清理中断时保留`CLEANUP_PENDING.json`，可用同一命令继续；已保存总稿先核对后才删除中间数据。不要在手工编辑内部产物或直接调用内部函数的同时清理；受支持的CLI提交和清理共用非阻塞任务锁。

旧0.1.5任务可以使用其原版本继续处理，或由本清理入口结束；清理旧任务不等于将旧表迁移到0.1.6。升级后的常规整理仍从来源新建任务。依赖保持不变，单独`cleanup_tool.py`只用Python标准库。

## 正确顺序：每次提交都有可查看的稿件

1. 填 **01_输入.xlsx** 的接入根目录（B9）；输出目录、模板可在表或命令行声明。输出留空会在包根 `outputs/首稿_时间_随机号` 自动建立新任务，根目录确实是唯一必填。
2. `scan` 递归冻结/识别后 **立即按整篇来源生成首稿**，同时给出02扫描核查、03反馈提交。待审文字按正文保留原文原号；实际图表有SEQ序号，公式不编号。不会等待分类核查才出首稿。
3. 人或Agent只改02中需要调整的归类、顺序、整篇/拆分、显示题名，在B6选择“确认本表”；`classify` 在新目录生成分类后的新稿。下一张02从本次确认计划回填，连续分类可以只改顺序，其余已确认归类/题名/排除保持。
4. 在03集中提交局部反馈，B6选择“提交本表”；`feedback` 验证整批后只构建一次新稿。可逐批继续提交，每批生成新稿，无固定最多两稿。
5. 已应用项在新稿检查通过后关闭并保留历史。暂缓、保留、未定位、执行缺口分开报告；不把未定位意见当已修改。

**正常整理保留原件、冻结模板和旧稿。** 用户显式结束任务并清理中间数据时，先保留各阶段总稿，清除任务内部快照与表单；原输入和任务外模板仍需保留。能读入的来源继续入稿；损坏/不支持来源以缺口标记和原件附件明确报告。发现缺口不会拒交其他内容，不能把缺口说成完整搬入。输入绑定破坏、非法新路径等不能猜着执行，此时保留已经存在的稿件。

## 安装与运行

Python 3.10+。核心唯一第三方依赖 `lxml==6.1.3`。不需要模型SDK、Node、python-docx或Pillow；后两者仅用于包外测试。Windows WPS可选；读取真实物理首页或转换DOC需另装pywin32（`python -m pip install pywin32`）。纯DOCX且关闭首页检查时不需要。

```powershell
python -m pip install -r requirements.txt
python -B report_tool.py doctor
python -B forms_tool.py init --out "D:/资料/输入.xlsx" --root "D:/报告根目录" --run "D:/任务/首稿01"
python -B forms_tool.py scan "D:/资料/输入.xlsx"
# 修改首稿01/02_扫描核查.xlsx，B6确认本表
python -B forms_tool.py classify "D:/任务/首稿01" --out "D:/任务/分类02"
# 修改分类02/03_反馈提交.xlsx，B6提交本表
python -B forms_tool.py feedback "D:/任务/分类02" --out "D:/任务/反馈03"
python -B forms_tool.py status "D:/任务/反馈03"
```

也可使用 `run.cmd forms ...`。所有输出目录必须全新，中文/空格路径支持。包内 `forms/01_输入.xlsx` 可直接复制填写；02和03只能由实际任务生成，含该任务来源与稿件绑定，不能复用别批空壳。

输入表行9—15：B9根目录、B10模板、B11新输出目录（留空自动创建）、B12总稿名、B13核查方式、B14启用WPS首页检查、B15 DOC转DOCX预处理。默认人工核查也先交首稿；Agent辅助仍由外层Agent填写同一表单。显式“接受程序建议”在交首稿后自动采用建议，再生成分类稿。B14选择“启用”或使用`scan --pages wps`，程序在识别前只读副本提取物理首页，作为前置范围的补充证据和月报拆分依据；不按首页整页删除。默认关闭。B15默认启用，遇DOC才启动WPS另存DOCX，关闭/不可用/转换失败列明确来源缺口并继续交其余稿。`init --pages wps --doc-conversion wps`可预填；旧off/wps值兼容。

## 三表各改变什么

| 表单 | 可编辑 | 作用 |
| --- | --- | --- |
| 01输入 | 根目录、模板、输出、题名、核查方式、首页读取 | 递归接入DOCX及可转换DOC；不要求提前列文件清单 |
| 02扫描核查 | E处理决定、F归类、G顺序、H显示题名、I备注 | 改整个内容单元的组织；A:D来源事实不能改，不删除/调换行，用G改顺序 |
| 03反馈提交 | D类型/E值/F说明/G范围/H决定；空白新行还可填B文档定位/C原文 | 批量修改局部结构或排版。程序导出的ID/B/C/I为事实，不能改 |

归类用 `/` 分层；同归类的单位聚合，按首次出现的排序决定组顺序。整篇保留抑制子单元，拆分仅采用已给出的完整边界。默认所有内容纳入，只有明确“不纳入”才排除。

## 填表规范与示例

三张表都是固定输入接口，可用 WPS 表格或 Excel 填写，保存为原 `.xlsx`。只填写文字/数字或选择下拉值，不填公式、不加宏/外链，不删除隐藏绑定页。不要改表头、程序ID或固定事实列。每次从**最近一稿目录**取新表，提交到新的输出目录；不要把旧表套到新任务。只读“反馈处理回执.xlsx”不是输入表。

### 01：接入资料

| 单元格 | 填写规范 | 示例/留空含义 |
| --- | --- | --- |
| B9 接入根目录 | 必填，现存目录的完整路径；单元格内不加引号 | `D:/月报/十月`；递归读子目录DOCX/DOC |
| B10 目标模板 | 符合包内正文接口的现存DOCX模板路径 | 空白用包内模板；任意普通Word不是自动兼容模板 |
| B11 输出目录 | 尚不存在的新目录，或由 `scan --run` 指定 | 空白自动在包根outputs建新目录；`--run`优先 |
| B12 总稿名称 | 普通文字 | 空白用“工程报告汇总”；不改原件题名 |
| B13 核查方式 | `人工核查` / `接受程序建议` / `Agent辅助核查` | 空白为人工核查；都先出整篇首稿；接受建议会再交分类稿 |
| B14 启用WPS首页检查 | `启用` / `关闭`（兼容wps/off） | 默认关闭；本机WPS/pywin32，只读副本提取实际首页，失败继续出稿 |
| B15 DOC转DOCX预处理 | `启用` / `关闭`（兼容wps/off） | 默认启用，遇DOC才调用本机WPS；保留二进制及转换回执，失败单列缺口 |

### 02：归类、顺序和取舍

从第9行开始。**A:D固定；只编辑E:I，用G调整顺序，不在工作表中排序/移动/删除行。** 检查后B6选`确认本表`。这是当前组织计划的完整提交，空值有明确含义；它不是“仅发送改动单元格”的补丁。后续表由程序回填已生效计划，所以只改一格也可保留其他已确认决定。

| 列 | 填写规范 | 作用 |
| --- | --- | --- |
| E 处理决定 | `接受建议` / `整篇保留` / `按建议拆分` / `不纳入` | 空白等同接受建议；整篇保留抑制子单元；仅按已有安全建议拆分；不纳入为明确排除 |
| F 目标归类 | `/`分层，如`测试任务/传感器` | 空白表示根层，不等于保持旧分类。每层1—100字，不填`.`、`..`；实际总层级不超过Word九级 |
| G 同级顺序 | 1—999999整数，不能空白 | 数字小优先；同值按程序稳定顺序；同分类聚合，不保证不同分类任意交错 |
| H 展示标题 | 1—200字普通文字 | 空白使用来源建议题名；不改文件名、不重写正文 |
| I 备注 | 供人/Agent解释意图的文字 | 不把自由描述当执行指令；可执行要求须填对应字段 |

例如某报告F填`试验分析`、G填`20`、H填`传感器复核`，另一份报告E填`不纳入`。取得新稿后，从新稿目录02只改G为`10`，先前分类、题名、排除均应保留。无特殊要求时保持程序生成值。整篇与拆分单元不能重复纳入；新增文件须重新扫描，不手工追加02来源行。不能全部排除后生成假空稿。

### 03：局部反馈

从第9行开始，B6选`提交本表`。程序已有事项的**A/B/C/I不改**，只填D:H；追加意见使用预留空白行，A/I留空，可填B/C及D:H。当前预留30条新增意见，更多可在下一稿分批提交。每行表达一个位置的一类修改；同段同类重复意见先合并。整批提交一次，生成一份累积新稿。

- **定位B/C**：B填`master | S0001:b000003`，或B只填`master`、C粘贴可唯一匹配的源文片段；ID取自当前稿定位索引，不能从另批猜。单篇用该稿实际文档ID代替master。未唯一定位的意见保留到下一表，不随便选一个位置修改。
- **D/E修改**：按下表填写；F写问题说明。F里的自然语言不会自动转换为脚本指令。
- **G范围**：空白/`仅此处`局部执行；`本单元`/`全文`当前记录为需要明确计划的保留项，不自动扩大修改。
- **H决定**：`提交修改`执行D/E；`暂缓`或空白保持待处理；`保留原样`仅能关闭程序已有事项，不用于新空白行。生成并检查新稿后才关闭已应用项。

| D 修改类型 | E 填写值 | 示例 |
| --- | --- | --- |
| 标题级别 | 来源级别整数1—5，不是总稿最终级别 | `2`；分组/来源级别自动叠加，数字删除仍经授权检查 |
| 改为正文 / 改为列表 | E留空 | H选提交修改，保留技术原文 |
| 题名关联 | `图:块ID`或`表:块ID`，同来源真实对象 | `图:b000007` |
| 字号 | 5—48有限数字，单位磅，不加单位字 | `14` |
| 对齐 | 左对齐 / 居中 / 右对齐 / 两端对齐 | `居中` |
| 首行缩进 / 段前 / 段后 | 0—144有限数字，单位磅 | `0` / `6`，不是字符数 |
| 行距 | 0.5—3有限数字，单位倍 | `1`为单倍 |
| 目标归类 | 与02的F列相同，作用于定位所在内容单元 | `试验分析/传感器`；空白移到根层 |
| 单元顺序 | 1—999999整数 | `10` |
| 内容缺口 / 其他 | E/F写所需说明 | 保留为明确待处理事项；不自动补写技术内容或改全局规则 |

**悬置不是交稿失败。** 暂不能判级的文字按正文保留，题名/引用无法配对时局部保留，稿件仍交付并列待办。需优先修补的是内容丢失/改坏、取舍或累积决定丢失，以及合法分类/反馈无法继续出稿。来源损坏/不支持须单列整篇缺口，不能把缺口写成完整成功。绑定被改、旧稿被手工改过或输入值非法时拒绝本次提交，已有稿件仍可用。

反馈B列 `master | S0001:b000003`，或只填 `master` 并在C复制可唯一匹配的原文。标题级别填写来源级别1—5；目标组层级自动叠加。题名关联填 `图:b000003` 或 `表:b000004`，须同一来源真实对象。字号/段前/段后/首行缩进单位磅；行距填倍数；对齐填左对齐/居中/右对齐/两端对齐。默认仅此处；全文/本单元请求记录待明确计划，不偷偷变成全局规则。内容缺口/其他保留为开发事项。归类/顺序可通过反馈修改定位所在内容单元。

## 月报、任务树与编号

- 文件树与目标组织树分离，移动完整单元，不移动硬盘原件。根文件原顺序；子目录默认任务分组。首稿全篇，分类提交后才使用建议拆分。
- 有标准封面/目录的报告整体保留；月报需首页工作清单与后文唯一、已确定H1边界一致。缺少真实首页时只可使用显式分页前的“开头片段”，回执明确它不是物理页。
- 项目介绍/清单、未匹配章节、问题/计划保留。含跨边界书签、REF、章节文字引用或同一自动列表实例的来源保守整篇，不猜断点。
- 拆分生成有逐块原始位置映射的临时DOCX；仅已授权标题前缀按新单元重排，其他文字/对象逐块比较。临时文件不替代冻结原件。
- 相同单元重复准备保留冻结ZIP成员元数据与顺序；目标展示题名独立于源单元题名。只调整归类、顺序、展示题名时，未变源单元的已确认结构/字号等继续继承，不降低完整来源哈希校验。
- 任务组H1、报告题名H2，源H1—H5顺延为H3—H7。无任务组时仍为来源H1、源H1—H5→H2—H6。准备后的模板H7—H9沿用H6外观，原模板及封面不动。Word最多九级；不能静默压平。
- 图表全文SEQ、可解析唯一REF/数字书签迁移，标题与列表编号隔离，沿用原内核独立检查。公式暂不编号，原生OMML/图片/表格保留。

## 文件与运行数据

`forms_tool.py`与`src/wps_pipeline/form*.py`、`verify_forms.py`是新增适配；原 `report_tool.py/batch_tool.py`继续处理结构判断、编号授权、装配、公式和检查。新增独立组织树检查核对实际目标层级。XLSX是固定惰性OOXML表单，支持WPS/Excel保存的inline/shared string，不执行公式/宏/外链，不增加openpyxl依赖。

每次任务：`source_scan`冻结原件与原始事实；`inventory.json`物理树/建议；`approved_plan.json`确认计划；`prepared`有映射的单元/模板；`draft_001`为原内核完整任务、总稿、单篇、定位索引与收尾回执；三份表单及`feedback_ledger.json`。新修订始终从冻结来源和累积有效决定生成，不能把人工改稿倒灌为原件。

## 验证口径

安装诊断不等于文档准确率。候选自测、第三方实测、WPS首页/编辑、页面视觉分别记录在包外交付报告。程序模型API=0；外层Agent精确token不可得记null，不编造。Clean只含实现/模板/必要说明，Full另带本批复现脚本和证据；不混入旧工程。模型审查只是独立测试反馈，不能替代用户业务验收。

## v0.1.2 接入与前置处理

- DOC→DOCX是本机WPS另存副本，不是改后缀；原始文件、转换副本、输入/输出SHA、当前WPS二进制版本、可观察文字/对象数量及失败原因留在`preprocessing.json`和`preprocessed/`。WPS保存成功不等于技术语义已证明无损；转换与入稿状态分别报告。0.1.3已补旧公式/OLE载体保留，范围见下文。
- WPS只用DispatchEx，通过文档窗口PID证明归属，只读本批副本；无Dispatch回退，不关闭用户已有WPS。每份有执行期限，失败不吞掉其他来源。首次识别之前读取首页；后续轮次继承冻结事实，不反复打开WPS。源COM位置仍为当次临时地址。
- 前置范围同时保留真题名、排除明确机构/部门/作者/日期、前置空段及有证据的目录。补单空格页码目录；目录正文匹配仍作识别线索。机构规则只在前置且有明确元信息时生效，正文同名词不全局删。
- 已支持一、二、/（一）/一 空格；补一.、一．、一）等相邻序列。它们先进入标题/列表候选，依据上下文分组；不能把“一台设备”按数字删去。首稿未决仍按正文原文保留。
- 拼写/分页缓存标记单独保真记录，不作为技术内容不支持而拒整篇。未绑定实际图表的旧SEQ冻结显示文字，不推进总稿序列。仍有引用的来源公式尾号局部保留并列待办，未引用尾号继续移除；独立检查核对原公式、原引用与实际输出绑定，不给所有旧号放行。
- 0.1.2当时对旧OLE/VML与缺失资源仍可能整篇缺口；这是历史边界。0.1.3的实际行为见下节，旧回执不回写。截图不能代替失败原件。

每轮输入输出及DOC路径详见[操作手册](操作手册.md)。旧0.1.1任务保持原版本，当前不提供跨代码三表迁移；不要手改SHA。母模板和旧WPS/Bridge/HRS发行保持。

## v0.1.4：图题怎样判断，何时局部保留

照片只能证明可见现象，不能读出源XML。看起来相同的图题可能有不同的样式继承、SEQ或大纲属性；不能以截图猜定原文件原因。当前规则如下：

| 环节 | 规则 |
| --- | --- |
| 实际对象 | 先从现代/VML图片、组图/布局表及数据表确定对象；对象编号不等待题名 |
| 题名候选 | 图/表完整旧号只是候选；同时看短题名、正文版式差异/居中/题注样式/SEQ及真实邻接。正常首行两格不是异常缩进 |
| 解释句 | “图9显示了……”等解释句保留正文；长正文、列表和技术量值不能因图号词头升为题名 |
| 普通同格式题名 | 即使与正文同为Normal、顶格，紧邻图片下方/表格上方的紧凑图表号+名称也可作证据；不能跨实质正文找普通题名 |
| 标题样式误用 | 题名候选仍核邻接和内容，源样式继承outline不再提前跳过图题判断 |
| 连续图片题名 | 一图一题容量约束；末端明确配对后，剩余候选可变为唯一，再逐步消解。真正孤立并列歧义或竞争题名保持局部待审 |
| 写入 | 确认题名保留技术文字，精确迁出完整旧号，以总稿SEQ重编号，引用只随唯一对象改号 |
| 不能确认 | 图片仍有纯号码；旧题名文字另保留并记03。这不算关联已解决，也不因悬置拒交总稿 |

新增局部处理：
- 扫描清点所有书签标记，包括正文容器和域内标记。不完整、重名/重号或跨前置排除范围的书签只解除相关标记；显示文字及对象保留，依赖引用按既有规则冻结。有效书签/数字书签/REF仍迁移。独立检查不允许借此删除完好的书签。
- 原公式无安全行间转换条件时保留原OMML与现有文字、列equation_layout_retained，继续入稿。未引用纯尾号仍移除；确有原文引用的旧号按绑定例外局部保留。不以“套样式”冒充行间容器转换完成。
- 旧图内文本框的来源段落样式另映射，保留直接字符格式并物化可得的继承字体/字号。图内故事不再被普通正文数学转换器改写。几何、文字、图片及嵌入数据保持。
- 若无法读入整个文件，仍交其他稿并明确整篇缺口；用户输入/绑定被改、权限或路径非法仍要明确错误，不能伪造成功。技术内容的独立检查仍保留。


未配对题名中的旧前缀保留时会明确列为未迁移；不会因整段保留就忽略同段其余唯一图表引用。完整的短说明句也按正文核对，不能只用30字长度线判定；中心、上行等名词不会因首字被当成解释句。

## v0.1.5 中文相对层级与局部编号回退

“一、二、三、”及点/全角点/空格变体先作为同一章序列的候选；仍核正文展开、列表引导、冲突与真实父级。中文章下1.1/1.2或1、/2、、1./2.、1 空格/2 空格，可作为相同的小节层级。最后一章不必等待不存在的下一章来确认层级；每章重新从1开始不沿用前章分组。同组标点混用仅在已建立的中文层级语境中归并，原前缀与删号授权保持；中文操作步骤不会仅因一/二/三而升级标题。

未知自动编号的事实、理解和搬运分开：完整自包含定义及全部实例可原样迁移，含表格单元格；缺定义、非自包含链接、非法级别或实例不完整，本处用“[原自动编号待核] ”明确代替无法可靠解析的标号，文字、图、表、公式继续入稿。原编号事实/定义与原件仍在冻结来源，收尾列automatic_numbering_label_unavailable；它是局部编号显示缺口，不是已恢复旧号。不能把整份来源占位冒充全文内容已纳入。

安全绑定、技术内容与模板检查继续；真正无法读取的文件或不可安全搬运的对象仍明确报告，不能任意catch异常后写PASS。原38Python职责保留，独立检查与生产计算的必要重复不合并成互相证明。JSON写盘使用唯一临时文件及有限共享锁重试，写失败保留旧JSON。

第三方复核补充：行首“1.5 倍安全系数”及计数/像素/周期等量值先进入量值或明确歧义保护，不自动删号；“按准备、采集、复核三个步骤执行。”这种叙述不作列表引导。已有连续章序与明确列表引导冲突时只该节点待定，不把后续章全部变成列表。03按同源同块同语义合并单篇/总稿镜像，结构待审的两种内部kind合并为一行；其他不同问题仍分条。绑定保留related_documents/related_kinds，原完整事项在core记录；格式反馈仍仅所选文档和位置，不因去重自动扩大。
完整未知编号包括正文内嵌套表格/文本框；先归一故事样式再恢复编号，避免擦掉定义。若同一未知实例还用于不搬运的页眉/脚注等故事，明确本处编号显示缺口，不声称已携带完整实例。拆分单元子标题不能安全重建时逐块原文原号复制并记原因，下游继续判断，不中止整次分类。
