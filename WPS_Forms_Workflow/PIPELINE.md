# 三表数据流

诊断身份由maintenance读取实际三表代码/内核协议，并核BUILD_INFO/config/发行清单；doctor同时展示三项版本，不把协议号当三表发行号。

完成整理后可显式进入维护支线：`cleanup_tool.py <任务父目录>`预览，`--apply`保留各轮阶段总稿后清理内部产物。任务没有改变到新版本，清理也不恢复结构判断；CLEANED_TASK/PENDING使后续旧表提交给出明确说明。`--keep-latest`保留最新任务和其修订链。CLI assemble/classify/feedback与清理共用非阻塞任务锁，未知根文件/原件/用户模板保持。默认不自动清理每一轮，避免刚出稿就丢失反馈所需数据。

```text
根目录 + 目标模板 + 新输出路径
  → 固定输入表 / init
  → scan: 递归DOC/DOCX树 + 冻结原件
  → DOC按01开关WPS另存DOCX（失败列缺口）
  → 按01开关只读WPS物理首页（失败局部回退）
  → 冻结源/模板 + 原Scanner/前置范围/识别器
  → 原装配器 finish + 原独立检查 + status
  → 首稿（整篇来源，待审文字为正文） + 02核查 + 03反馈
  → classify: 一次确认目标组织/完整拆分范围
  → 有映射的单元准备 + 覆盖/前缀/对象独立检查
  → 新目录分类稿 + 从已确认计划回填的新02 + 新03表
  → feedback: 整批定位/合法性 → 累积决定 → 一次新稿/检查
  → 检查后关闭有效项 + 保留历史 → 下一批可重复
```

## 权责

人决定业务归类/取舍和可用程度。外层Agent可代填局部判断，调用同一命令。固定程序负责批量连续执行、编号、对象迁移、冻结、检查和回执；程序不调用AI。AI不在场时，人填Excel即可执行。

## 固定文件

| 数据 | 内容与消费者 |
| --- | --- |
| inventory.json | 来源SHA、冻结路径、物理目录、程序单元建议、忽略项；表单与派生检查共用 |
| forms_state.json | 任务标识、清单/运行代码摘要、当前稿、分类/反馈状态、用量 |
| preprocessing.json / preprocessed/ | 二进制原件、转换副本/回执；转换与装配独立计状态，后续轮继承 |
| page_facts.json | 本批物理首页补充事实，不按整页删正文；缺少WPS时仍继续 |
| source_scan/ | 原内核准备任务：原件、扫描事实、候选、封面/目录证据；原始事实不被表单改写 |
| approved_plan.json | 归类/顺序/展示题名、纳入/排除、来源边界、派生映射、模板准备；不等于语义真值 |
| prepared/ | 拆分单元及单独准备的模板，不是永久原件 |
| draft_001/ | 新目录中唯一一次本批build；原内核state、DELIVERY、finish_list、总稿、定位索引 |
| feedback_ledger.json | 已应用/保留/未定位/范围待明确/执行失败；检查通过才关闭 |

## 来源到目标

02的A:D程序事实固定，E:I承载用户意图。物理路径不作为目标章节编号。目标组织树聚合同组单元，按用户顺序形成遍历；树中的每个分组/来源实际占级。装配前从树计算前缀；独立检查重新遍历树，并回读DOCX的真实样式、大纲标签、对象号和引用。

02为完整计划表，不是单元格差异补丁。连续分类先保存本次确认计划，再导出下一张02，不能回到inventory初始建议。只改顺序时，已确认归类、展示题名、排除继续有效。初次未核查表仍是程序建议。枚举、空值、单位和示例见README“填表规范与示例”。

月报拆分仅在首页清单/已确定的正文H1边界相符时给出，且不得切断书签、内部REF、章节引用或同一自动列表实例。介绍及未匹配章节均形成单元。无真实物理页时，显式分页前的片段独立标注，不能谎称WPS首页。安全证据不足则整篇。默认首稿不拆，因此即使分类后来需要调整，也已有完整稿。

派生单元保留相同资源/样式/编号部件。仅章标题经既有权限去掉旧前缀、确定性重排；原始块映射覆盖全部区间。图/表/OMML/技术正文不通过模型重写。独立准备检查对照冻结XML，不使用识别测试truth。

## 反馈

程序导出的问题绑定当前稿、输出SHA与来源定位；新增问题先唯一定位。有效结构决定按来源集中resolve，格式覆盖按局部定位累计，组织反馈改显式树。整批验证后只revise/finish一次，旧稿保留。不确定/范围扩大/内容缺口可保留继续出稿。原文被手工修改时保留手工稿，不能套旧索引自动覆盖。

原batch_tool.py prepare-review/checkpoint继续支持JSON语义评审批次，仍按原生有效决定/父链闭环；三表不另建模型客户端。当前修订仍重扫冻结来源，未做扫描缓存。一次成功运行不代表未知真实报告准确率。

## v0.1.3 对象保留与引用降级

- WPS公式编辑器 Equation.KSEE3 / Equation.* / MathType.* 的嵌入载体、原始二进制和预览一起搬运；带equationxml的旧式公式也保留原载体。不把它们解析成OMML、不转成普通图片、不执行嵌入对象。识别出公式载体不代表已理解公式含义。
- VML w:pict/v:imagedata与现代图片均纳入实际图片清单，同段组图整体编号；公式预览不占图号，空DrawingML壳不虚增图号。可保留的正文容器及内部对象继续入稿。
- 唯一可迁移的图表SEQ、书签和REF仍保留原生关系。不能可靠迁移的完整REF/PAGEREF/NOTEREF解除域，只保留当前显示文字及缓存内对象；不猜新指向或新页码。原指令、来源和降级记录留在装配报告。新稿检查通过后记为completed_actions，不反复导出为同一03问题。
- Edlén公式3×10^-8、GDS文件格式126原文保持，不以“式+数字”子串改文或拒收；普通文字的真实公式引用和仍需保留的旧公式号另记局部事项。
- 图片同时有有效内嵌数据及外链时使用内嵌数据、解除外链。真正没有媒体数据或仅有未随包外链时，只在原对象位置用明确缺图占位并附关系/块定位，其余正文与对象继续搬入。不会下载外链或编造原图。local_media_gaps与整篇gaps分别计数，全部来源搬入不等于缺失像素已恢复。
- 原件、母模板、历史任务和旧稿保持。三表列和命令不变；从最新稿的02/03继续提交。旧任务有代码绑定，当前无跨代码三表迁移器；升级后从冻结原件新建任务，不手改运行SHA。

## 0.1.4 的降级发生在链条中
扫描新增完整document_bookmarks事实，不用段落可见文字推算标记。前置范围与题名识别之后，装配按原XML和保留范围重算书签配对；只能解除有证据的不完整标记。依赖引用保留缓存显示。公式提升失败只局部保留原容器。图内故事样式和正文样式分开处理，正文数学转换跳过原绘图载体。独立检查从原件分别核这些条件；已完成元数据解除通过后转completed_actions，仍未处理的版式保留到03。每次提交仍只有一次新总稿，不增加Agent逐步串接。

## 0.1.5 首稿中的两类编号
中文父章和阿拉伯子节先恢复相对树，再叠加任务组/来源深度；标点与数字位数不是固定目标层级。自动编号原定义可完整携带则隔离迁移，不能可靠解释的标签局部显式待核，其余内容继续。扫描仍只记录原始事实，编号组/层级在候选层。首稿/分类/每批反馈均需实际Word、独立检查和status，不以疑点清零阻塞。

量值保护先于marker_family分组；中文章序与列表引导冲突只局部待定。反馈导出合并同源同块结构重复项及单篇/总稿镜像，保留原事项/关联文稿，默认修改仍仅当前文档。拆分子标题重建失败保留该块，不丢原内容。
