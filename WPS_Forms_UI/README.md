# WPS 文档整理 · 本地界面 0.1.2

界面复用**原样三表0.1.6 / 内核协议0.5.7**，不调用模型API。原件→首稿→分类新稿→每批反馈新稿。实际排版在WPS查看；网页提供原稿/当前稿的前后文、来源及定位入口。本版不依赖PDF，不提供页面图像或网页Word编辑器。

第一栏“模板样式工具…”入口唤起模板工具1.0.3的独立Python窗口。本机环境栏分别显示界面版本/构建、三表版本/构建及内核协议；发行清单从实际代码和BUILD_INFO读取身份，当前值见根目录COMPONENTS.json。

## 启动

1. 解压完整目录，双击`启动界面.pyw`（需要已安装Python并有关联）。选择本机可读取文档的`python.exe`，点击“启动 / 打开整理界面”。文件关联不可用时，用该Python运行`启动界面.pyw`。
2. 浏览器自动打开本机`127.0.0.1`界面，服务仅监听本机回环地址。启动器与网页均保留错误，不需要运行PowerShell脚本。启动器关闭不会关闭服务或Word；网页“退出服务”负责结束服务，Word窗口保留。
3. 核心依赖为相邻`WPS_Forms_Workflow/requirements.txt`中的lxml。原生WPS定位、DOC转换及首页读取还需要该Python装有pywin32，以及本机WPS。缺少原生接口时，可用“仅打开”查看副本，但不宣称完成定位。

命令行等价入口：`python -B ui_tool.py serve`。源码开发默认使用相邻`WPS_Forms_Workflow`；独立包默认使用包内`core/`。可显式指定`--core 完整目录 --data 本机数据目录`。完整数据目录可以备份；任务包含版本与路径绑定，跨机或改变任务路径后的接续迁移尚未实现。不要只复制其中的某轮总稿后期望继续修订。

可在已激活的Conda环境、CMD/Anaconda Prompt中直接运行，启动异常留在终端：

```bat
cd /d "D:\工具\WPS_Forms_UI"
python -m pip install -r requirements.txt
python -u -B ui_tool.py serve --data "D:\WPS整理数据"
```

路径替换为本机实际位置。依赖首次安装即可；Conda环境中的模板弹窗/文件选择器需要Tk支持，缺少时在该环境执行`conda install tk`。Tk不通过pip安装。WPS原生能力仍按上方要求安装pywin32及本机WPS。

正式使用无需Node、npm或开发代理。保留原版程序和完整数据；如用新版接续原界面数据，先退出原服务，再由所选Python运行新版`ui_tool.py serve --data 原data绝对目录`。保持原任务路径，由底层检查既有绑定，不手改版本号或哈希。本次发布没有移动、清理任何旧任务。

## 操作顺序

### 01 新建整理

根目录为唯一必填项；目标模板留空使用包内模板。输出目录必须全新，留空在本机数据目录自动生成。WPS物理首页默认关闭，DOC转换默认启用。点击“开始整理并生成首稿”，固定程序连续运行到装配、检查和交付。宽屏右侧显示真实事件与程序输出，默认筛选“阶段与交付”；可改看全部或错误。窗口宽度不超过1100像素时初始收起日志，可随时展开。

首稿已包含可接入内容；不能判级的文字按正文保留。局部疑点和整篇缺口分别记录。首稿交付后自动进入02；有任务目录不代表已经有总稿，顶部以实际输出为准。界面不会逐项等待AI，也不会自动反复重试。继续已有任务时，选择含`forms_state.json`的完整任务目录；旧版本绑定不绕过。

“目标模板”旁的“模板样式工具…”会打开独立桌面窗口，用启动界面的同一Python运行。先选择带封面/目录/页眉的DOCX，读取并选择正文起点，保存为新模板；回到01点“选择模板…”选这个输出文件，再开始整理。该入口不自动改变当前目标模板，不修改已开始的任务。工具内原有的样式来源、指定Python及诊断选项保留；默认指定当前界面的Python。

工具源码来自公开1.0.3包，所需10个模块、原配置/两模板及许可来源在`tools/template_style/`，用独立子进程隔离同名模块。没有嵌入EXE/环境；所需lxml已在界面依赖中。当前服务内重复点击会提示切换已有窗口。窗口就绪与关闭在日志记录，失败不影响总稿整理；关闭本地服务不会强制关闭独立模板窗口。直接唤起工具的等价命令为`python -u -B ui_tool.py template-tool`。

### 02 分类与顺序

只编辑处理决定、目标归类、同级顺序、展示题名及备注。归类用`/`分层，顺序填正整数；整篇保留/已有安全建议拆分/明确不纳入沿原三表规则执行。提交后只生成一次分类新稿，载入新02/03并进入03。没有组织调整时可直接切到03，无需为了前进而提交空分类。

顶部“本批工作”和页签状态区分未同步修改、外部Excel待同步、已同步但待生成新稿及终稿确认。路径默认显示稿次/文件名，悬停可看完整路径；技术定位与版本绑定仍可展开核对。外部文件是否改变以实际读取/同步为准，最终提交总会由后端重新核查，状态文字不代替核查。

### 03 反馈与修订

选择事项或新增意见。新增意见填写文档定位（如`master | S0001:b000003`）或可唯一匹配的原文片段，先点“同步并定位”。修改类型、单位及范围与原Excel一致；标题级别是来源级别1—5，字号等为磅，行距为倍数，默认仅此处。范围扩大、缺口及无法定位仍可保留，不猜着修改。

事项旁显示唯一定位状态，上一处/下一处只切换当前事项。没有待核事项时显示“新增第一条意见”；也可直接核查当前总稿并确认完成。没有新增或已填写修改时，不必生成一轮空反馈。

网页列出完整来源文件、来源章节、当前总稿章节和两端前后文。“同时打开并定位两份Word”由本机WPS打开两份**只读查看副本**，临时书签只加在查看副本中，原件、冻结输入、总稿及绑定索引不改。拆分单元按既有映射回到整篇冻结原稿；无唯一位置时明确报告。两份文档在WPS中查看、可自行并排；本版不保证不同WPS版本都自动形成两个并排窗口，也不联动滚动。

填写一批意见后，“提交本批反馈并生成新稿”只调用一次原feedback流程。新稿由冻结原件与累积决定生成，旧稿保留。若另一页还有待提交修改，会提示先处理，避免切换稿次时遗漏。每次都从最新稿继续，不把旧总稿作为新来源。历次稿件始终可打开。

## 界面、Excel与Agent共用输入

- 任务目录中的`02_扫描核查.xlsx`和`03_反馈提交.xlsx`仍是原内核输入；Agent可继续使用原CLI及其`--origin model`。
- 界面工作记录在`data/tasks/`，不充当第二套已确认决定。**同步**按上次基线、当前界面及当前Excel作三方比较；不冲突字段合并，同字段冲突必须明确选择。事实列和隐藏绑定保持；Excel被占用时先保存关闭再同步。
- 提交前必须同步，随后冻结一份提交副本，设置原B6确认项，调用原CLI；旧表在执行期间被外部编辑不会悄悄改变本批输入。生成后加载新任务的新表，不重用旧稿定位。
- 导出副本带本机导出基线标识，导入时检查当前任务绑定并比较修改；跨任务表单不会被接收。网页未同步的编辑在同一浏览器地址暂存；离开前应点击同步，跨浏览器/服务地址不要依赖浏览器草稿。
- 顶部“本批填写者”区分人工填写与Agent代填，写入原反馈来源；Agent不能因使用界面就冒充人工判断。自动化操作应选择“Agent代填”；使用人工选项的合成演示仍是模拟数据，不是真实人工标注。

## 最终完成与数据保存

第三页“确认当前稿为最终版本”要求两表已同步、没有已填写但未生成的决定、当前稿检查可交付；执行中暂不开放确认和数据保存。存在未决项时须明确接受保留，不要求为了终审把所有保留项强行判定。执行或内容缺口尚未修复时，草稿仍可查看和继续反馈，但不能标记最终完成。

确认绑定稿件SHA、任务状态及两表，确认后开放第四页“完成与交付”。有待提交修改时先关闭终稿入口；若明确撤销且原绑定仍相同，已有确认可继续有效；一旦生成新稿就需要重新确认。是否有效由后端核对，不仅看浏览器按钮。

第四页以“打开最终总稿”为主要操作。展开“可选：保存本轮修正数据为训练集”，再点击“保存本轮修正数据”，才会导出明确且已检查的人工修正、单列模型候选、保留历史、组织计划、来源及扫描/候选依据。原件按SHA去重。自动规则、默认正文回退、未决项以及整稿终审不会自动成为真值；组织决定、字号等偏好须按用途进一步筛选。模型候选没有人工确认，不作为人工标签。本功能只保存数据，不训练网络。相同母本及格式变体还须归同一分组后再划分训练/验证集。

**先导出并核对数据，再使用内核的清理功能。** 内核cleanup仍是原显式维护入口，默认预览；本界面不自动清理，也未重新验证删除分支。

## 每轮多出的文件

| 位置 | 内容 | 下一轮用途 |
| --- | --- | --- |
| `data/runs/任务…/R01_首稿` | 原三表完整任务及首稿 | 从此轮02/03继续 |
| 同父目录`R02_分类…`、`R03_反馈…` | 每次提交生成的完整新任务、累积总稿及新表 | 始终使用最新一轮 |
| 每轮`draft_001/build_001/documents/master.docx` | 本轮实际总稿；具体地址由内核回执给出 | 查看/交付，不能作为下一轮来源 |
| `data/jobs/批次ID/` | 冻结提交表、真实命令参数、输出日志、结果或失败现场 | 追溯一次提交 |
| `data/tasks/` | 界面同步基线、待提交记录及终稿确认 | 界面重开接续 |
| `data/views/` | 有临时书签的只读Word查看副本及哈希回执 | 仅供定位查看 |
| `data/tools/启动ID/` | 模板工具启动参数、独立日志及关闭回执 | 定位启动失败；生成模板保存在用户选择的新路径 |
| `data/training/` | 明确导出的修正数据 | 后续筛选/训练准备 |
| `data/ui_events.jsonl`、`launcher.log` | 连续运行日志、启动错误 | 查看问题；不凭日志出现就宣称通过 |

输出目录可在01另选；这时任务留在指定位置，界面工作记录仍在`data/`。手工修改的总稿保留，旧定位索引会被拒绝，不能自动覆盖它。

## 范围

组件版本与功能范围以代码及发布清单为准。程序检查、办公软件编辑和页面视觉属于不同验证范围；发布说明分别列出实际执行与未执行的检查。

组件内README来自原完整公开包，其中EXE/构建/测试说明仍属于原包；当前组件只包含COMPONENT_MANIFEST登记的运行闭包、两模板及许可来源。此界面没有修改模板工具1.0.3本体或三表0.1.6原内核。

WPS版本兼容性、文件读取差异、窗口排列、公式编辑器交互和页面视觉分别验证。程序模型API为0，Agent精确token/context不可得时记null。纯净包不含历史任务、样本、答案、日志、解释器或个人配置；需已有可用Python环境。
